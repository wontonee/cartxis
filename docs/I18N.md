# Cartxis Internationalization (i18n)

Cartxis ships multi-language storefront support with RTL for Middle East languages and language packs covering Europe and Africa.

## What is included

| Layer | Status |
|-------|--------|
| Locale registry (Settings → Locales) | Yes — includes `direction` (ltr/rtl) |
| Runtime `SetLocale` middleware | Yes — session, cookie, `?locale=`, `Accept-Language`, customer preference |
| Storefront UI strings (`vue-i18n`) | Yes — JSON catalogs under `resources/js/locales/` |
| Language switcher | Yes — default theme header |
| RTL (`dir=rtl`) | Yes — `ar`, `he`, `fa` (and `ur`) |
| Product / category translations | Yes — `product_translations` / `category_translations` |
| API locales | Yes — `GET /api/v1/locales`, `X-Locale` / `Accept-Language` / `?locale=` |
| Admin UI language | Yes — sidebar menus + chrome + Locales page (full packs: en/ar/tr/fr/de/es/pt/sw) |
| Extension UI language packs | Yes — `resources/locales/{code}.json` merged via `LocaleService` (see below) |

## Seeded languages (v1)

**Full UI packs:** `en`, `ar`, `fr`, `de`, `es`, `pt`, `tr`, `sw`  
**Partial packs (fallback to English):** `he`, `fa`, `it`, `nl`, `pl`, `ru`, `uk`, `am`

Install / seed:

Fresh installs run `LocaleSeeder` via `php artisan cartxis:install`.

**Upgrades** (1.0.17+): `php artisan migrate` runs
`2026_11_03_000001_seed_i18n_locale_catalog` so the ME / Europe / Africa rows
appear without re-seeding. It never resets your store default language or
deactivated locales.

Manual re-seed (safe — preserves default / active flags):

```bash
php artisan db:seed --class=Cartxis\\Core\\Database\\Seeders\\LocaleSeeder
php artisan cache:clear
```

## Merchant usage

1. **Settings → Locales** — activate languages, set default, mark RTL where needed.
2. The **default** locale drives the storefront for new visitors (browser `Accept-Language` no longer overrides it).
3. Storefront header language switcher sets a cookie + session (`cartxis_locale`). If you previously switched language while testing, clear that cookie or visit `/locale/tr` (or your default code).
4. Product / Category edit screens include a **Translations** panel for non-default locales.
5. **Admin** uses the same language switcher (header toolbar). Sidebar labels translate via menu keys (`admin.menu.*`).
6. Homepage hero / CMS blocks / storefront nav menus stay in the language they were authored — translate those in UI Editor / menus, or add product translations.
7. Mobile / API clients send `Accept-Language: ar` or `X-Locale: ar` or `?locale=ar` (explicit headers still win).

### Admin coverage vs Bagisto

Cartxis admin i18n covers navigation + shell + Locales settings in the seeded languages. Individual CRUD form copy is gradually moving to `admin.common.*` / page catalogs — contributions welcome for remaining screens.

## Developer: add a language

1. Add a row via LocaleSeeder or admin UI (`code`, `native_name`, `direction`).
2. Create `resources/js/locales/{code}.json` (copy `en.json` and translate). Missing keys fall back to English.
3. Rebuild assets: `npm run build`.
4. Optionally add PHP strings under `packages/Cartxis/*/Resources/lang/{code}/`.

## Extension language packs

Any extension (filesystem under `extension/{code}/` or bundled under `packages/Cartxis/*/`) can ship UI strings that merge into the same `vue-i18n` catalog used by storefront and admin.

### Layout

```
extension/my-feature/
├── extension.json
└── resources/locales/          # preferred
    ├── en.json                 # required baseline
    ├── ar.json                 # optional — missing keys fall back to en
    └── tr.json
```

`Resources/locales/{code}.json` is also accepted (PSR-style packages).

### JSON convention (namespace)

Always nest under `extensions.{snake_code}` so you never overwrite core `common.*` / `admin.*` keys:

```json
{
  "extensions": {
    "my_feature": {
      "name": "My Feature",
      "settings": "Settings",
      "description": "Manage My Feature"
    }
  }
}
```

`my-feature` → namespace `my_feature` (hyphens/dots become underscores).

If a pack omits the `extensions` root, Cartxis wraps the whole object under `extensions.{snake_code}` automatically.

### Vue usage

```vue
<script setup lang="ts">
import { useI18n } from 'vue-i18n'
const { t } = useI18n()
</script>

<template>
  <h1>{{ t('extensions.my_feature.settings') }}</h1>
</template>
```

Admin helpers (`useAdminI18n().common(...)`) are for core chrome; extension pages should call `t('extensions.…')`.

### Scaffold

```bash
php artisan cartxis:extension:make "My Feature"
# creates resources/locales/en.json + README
```

Add more locale files as you translate. No Vite rebuild is required for extension JSON — catalogs are loaded by PHP (`LocaleService`) and shared to Inertia on each request.

### PHP / Blade translations (optional)

Server-side strings still use Laravel’s translator:

```php
// In your ServiceProvider::boot()
$this->loadTranslationsFrom(__DIR__.'/../Resources/lang', 'my_feature');
// __('my_feature::messages.hello')
```

Inertia / Vue UI should prefer the JSON packs above so the language switcher updates them with the rest of the app.

### Programmatic merge

```php
add_filter('cartxis.i18n.messages', function (array $messages, string $locale): array {
    $messages['extensions']['my_feature']['settings'] = match ($locale) {
        'tr' => 'Ayarlar',
        default => $messages['extensions']['my_feature']['settings'] ?? 'Settings',
    };

    return $messages;
});
```

See also [EXTENSION-HOOKS.md](./EXTENSION-HOOKS.md) (`cartxis.i18n.messages`).

## RTL checklist

- Prefer logical CSS (`ps`/`pe`, `ms`/`me`, `start`/`end`) over `left`/`right`.
- `html` and theme root set `dir` from the active locale.
- Verify cart, checkout, and header at `/locale/ar`.

## Shared hosting

Locale JSON files are bundled by Vite into the app JS. Shared Hosting zips that include `public/build` already contain translations — no Node required on the server.

## Mobile parity

- `GET /api/v1/locales` — list + current
- `GET /api/v1/locales/default`
- Catalog resources honor active locale via `ProductResource` / `CategoryResource`
- Persist `customers.preferred_locale` when the customer is authenticated and switches language on the web

See also: [SHARED_HOSTING.md](./SHARED_HOSTING.md), [USER_GUIDE.md](./USER_GUIDE.md).
